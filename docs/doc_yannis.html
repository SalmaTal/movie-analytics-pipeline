    L’ingestion

    Récupérer les fiches de films sur TMDB et les écrire telles quelles en JSON Lines. Huit stations, dans l’ordre où on les a construites.

    Avant : rien, c’est le point de départ.Après : la transformation lit data/raw/movies/.

    La transformation

    La partie d’Aida : transformer les fiches JSON en tableaux propres et typés, au format Parquet. En une formule : normalisation + nettoyage + typage.

    Avant : les 27 fichiers movies/year=AAAA.jsonl de l’ingestion.Après : Salma charge les Parquet dans PostgreSQL, Aida les publie sur le Hub.
    { "id": 27205, "title": "Inception", "release_date": "2010-07-15", "budget": 160000000, "genres": [ Action, Crime, … ], "credits": { "cast": [ DiCaprio, … ], "crew": [ Nolan ×2, … ] } }
    →

    Parquet

    Pour stocker et analyser de gros volumes.

    • colonnes typées, fichier compact (589 Mo → 81 Mo) ;
    • on peut l’interroger directement en SQL avec DuckDB ;
    • mais il accepte tout : aucune règle de cohérence.

    PostgreSQL

    Pour garantir la cohérence et partager l’accès.

    • contraintes : refuse un movie_id inconnu ou un doublon de clé ;
    • chargement relançable sans doublons (upsert) ;
    • index mesurés avec EXPLAIN ANALYZE.

    Le code a été la partie rapide. Le vrai travail, c’est de comprendre ses données et de vérifier : sans mesure, on aurait perdu un film sur dix sans le voir.

    La base SQL

    La partie de Salma : ranger les 5 tableaux Parquet dans PostgreSQL, avec des règles que la base vérifie elle-même, puis les interroger. Dans l’ordre où ça s’exécute.

    Avant : les 5 tableaux Parquet de data/processed/.Après : 5 requêtes d’analyse et un test d’index.
    À noter (13 novembre) : rien dans le dépôt n’explique comment créer la base et lancer schema.sql. Le script de chargement suppose que c’est déjà fait.
